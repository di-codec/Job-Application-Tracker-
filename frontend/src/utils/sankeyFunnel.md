# Sankey Funnel — документация

Файл `sankeyFunnel.js` готовит данные для Sankey-диаграммы на главной странице (компонент `FunnelSankey.jsx`, библиотека Plotly).

---

## Общая схема работы

```
Заявки из API
      │
      ▼
STATUS_PATHS  ──►  для каждой заявки: цепочка рёбер по status
      │
      ▼
Подсчёт value  ──►  сколько заявок прошло по каждому ребру
      │
      ▼
Активные узлы  ──►  только узлы, участвующие в ненулевых потоках
      │
      ▼
buildNodeXPositions + buildNodeYPositions  ──►  координаты 0…1
      │
      ▼
trace для Plotly (type: 'sankey', arrangement: 'freeform')
```

Plotly в режиме `freeform` **не** расставляет узлы сам — мы передаём массивы `node.x` и `node.y`. Значения нормализованы: **0 = левый/верхний край**, **1 = правый/нижний край** области рисования.

## Граф воронки

### Узлы (индексы 0–9)

| Индекс | Имя | Колонка | Смысл |
|--------|-----|---------|-------|
| 0 | Applications | 0 | Все заявки (вход) |
| 1 | Interviews | 1 | Идёт интервью |
| 2 | Rejected | 1 | Отказ без интервью |
| 3 | Applied | 1 | Отправлено, ответа нет |
| 4 | Offers | 2 | Получен оффер |
| 5 | No Offer | 2 | После интервью — без оффера |
| 8 | In progress | 2 | Интервью в процессе |
| 6 | Accepted | 3 | Оффер принят |
| 7 | Declined | 3 | Оффер отклонён |
| 9 | Open offer | 3 | Оффер открыт (ожидание) |

### Рёбра (`SANKEY_LINKS`)

```
Applications ──► Interviews | Rejected | Applied
Interviews   ──► Offers | No Offer | In progress
Offers       ──► Accepted | Declined | Open offer
```

### Пути по статусу заявки (`STATUS_PATHS`)

| status в БД | Путь |
|-------------|------|
| `no_answer` | Applications → Applied |
| `rejected` | Applications → Rejected |
| `interviewing` | Applications → Interviews → In progress |
| `no_offer` | Applications → Interviews → No Offer |
| `offer` | Applications → Interviews → Offers → Open offer |
| `accepted` | Applications → Interviews → Offers → Accepted |
| `declined` | Applications → Interviews → Offers → Declined |

**Важно:** одна заявка добавляет +1 к **каждому** ребру своего пути.  
Пример: 8 заявок `no_answer` → `Applications → Applied` получает `value = 8`.

## Алгоритм расстановки по X (горизонталь)

**Цель:** активные колонки равномерно занять всю ширину диаграммы.

1. Собрать уникальные номера колонок среди активных узлов: `{0, 1, 2, 3}` → возможно меньше.
2. Для `n` активных колонок вычислить X каждой колонки:

```
x(i) = X_MIN + (i / (n − 1)) × (X_MAX − X_MIN)
```

где:
- `X_MIN = 0.02`, `X_MAX = 0.94` (отступы от краёв)
- `i` — порядковый номер колонки (0 … n−1)

**Особый случай:** если активна одна колонка → `x = 0.5`.

3. Каждый узел получает X своей колонки из `SANKEY_NODE_COLUMN`.

### Пример (4 активные колонки)

| i | колонка | x |
|---|---------|---|
| 0 | 0 | 0.02 |
| 1 | 1 | 0.327 |
| 2 | 2 | 0.633 |
| 3 | 3 | 0.94 |

Формула: `0.02 + (i / 3) × 0.92`.

### Пример (2 активные колонки: 0 и 1)

| i | x |
|---|-----|
| 0 | 0.02 |
| 1 | 0.94 |

Узлы «Interviews» и «Applied» (обе колонка 1) получают **одинаковый** x = 0.94 — они стоят в одном вертикальном «слое», но на разной высоте Y.

## Алгоритм расстановки по Y (вертикаль)

**Цель:** развести узлы в одной колонке по вертикали; выровнять «одинокие» узлы с предком для читаемых потоков.

### Шаг 1 — равномерное распределение

В одной колонке `k` активных узлов. После сортировки по `SANKEY_NODE_COLUMN_ORDER` для j-го узла (j = 0 … k−1):

```
y(j) = Y_MIN + (j / (k − 1)) × (Y_MAX − Y_MIN)
```

где `Y_MIN = 0.15`, `Y_MAX = 0.85`.

Если `k = 1` → `y = 0.5`.

### Шаг 2 — выравнивание с предком

Если в колонке **ровно один** узел и у него **ровно один** входящий поток:

```
y(узел) = y(единственный предок)
```

Пример: `Interviews → In progress` — «In progress» единственный в колонке 2, предок один → Y совпадает с Interviews, лента идёт почти горизонтально.

## Высота диаграммы

```
height = 220 + nodes×26 + columns×16 + min(apps, 20)×5
height = clamp(height, 320, 400)   // пиксели
```

Чем больше узлов, колонок и заявок — тем выше SVG (но не более 400 px).

## Пример на реальных данных

9 заявок: 7× `no_answer`, 1× `interviewing`, 1× `offer`.

**Потоки:**

| Ребро | value |
|-------|-------|
| Applications → Applied | 7 |
| Applications → Interviews | 2 |
| Interviews → In progress | 1 |
| Interviews → Offers | 1 |
| Offers → Open offer | 1 |

**Активные узлы и координаты:**

| Узел | x | y | Пояснение |
|------|---|---|-----------|
| Applications | 0.02 | 0.50 | колонка 0, один узел → y = 0.5 |
| Interviews | 0.327 | 0.15 | колонка 1, верхний (j=0 из двух) |
| Applied | 0.327 | 0.85 | колонка 1, нижний (j=1 из двух) |
| Offers | 0.633 | 0.15 | колонка 2, верхний |
| In progress | 0.633 | 0.85 | колонка 2, нижний (в колонке 2 узла — выравнивание с предком не срабатывает) |
| Open offer | 0.94 | 0.15 | колонка 3, один узел → y скопирован с Offers |

## Что рисует Plotly

- **Толщина ленты** (`link.value`) — пропорциональна числу заявок.
- **Толщина полоски узла** (`node.thickness = 18` px) — фиксированная.
- **Цвет ленты** — цвет целевого узла с прозрачностью 45%.
- **Неактивные узлы** — пустая строка в `label`, Plotly их скрывает.

## Частые вопросы

**Applications и Applied — это дубликат?**  
Нет. Applications — вход (все заявки). Applied — исход «нет ответа». Разные узлы, часто в соседних колонках или на разной высоте Y.

**Почему при 2 колонках справа пусто?**  
X считается только по **активным** колонкам. Если в данных нет путей до Offers/Accepted — колонки 2–3 не появятся, и 2 колонки займут x = 0.02 и 0.94.

**Plotly сам не расставляет узлы?**  
В `arrangement: 'freeform'` — нет. Мы полностью задаём `node.x` и `node.y`. Альтернатива `snap`/`perpendicular` — автолayout Plotly, но без контроля над воронкой.
